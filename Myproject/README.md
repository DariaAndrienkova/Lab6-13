# Трекер екскурсій та подорожей

Вебсервіс для обліку відвіданих місць, музеїв та екскурсій.

Для кого: для себе, щоб вести облік відвіданих місць, музеїв та екскурсій
Запис: дата, назва, категорія, вартість, тривалість, коментар
Операції: додати, показати всі, знайти за категорією, видалити (адміністратор)
Звіти: сума витрат за місяць, сума витрат за категорією, найбільша витрата

## Адреси

- API: https://api.andrienkova.pp.ua
- Сайт: https://andrienkova.pp.ua

## Запуск сервера

Потрібні два термінали в теці Myproject, у такому порядку:

    python -m waitress --listen=127.0.0.1:8000 app:app
    cloudflared tunnel --config deploy/cloudflared.yml run

Файл .env у теці проєкту :

    SECRET_KEY=довгий_випадковий_рядок


## Маршрути API та перевірка через curl
Маршрути для користувача (потрібен вхід, cookie ставить сам сервер):

    POST /register    {"login": "...", "password": "..."}   створює користувача і входить
    POST /login       {"login": "...", "password": "..."}   вхід
    POST /logout                                            вихід
    GET  /me                                                хто зараз увійшов
    GET  /items, POST /items, DELETE /items/<id>            лише власні записи
    GET  /report, GET /report/categories                    звіти за власними записами

Без входу всі ці маршрути (крім /register і /login) відповідають 401.
Чужий запис видалити неможливо: відповідь 404, ніби його немає.

Адміністративні маршрути (/admin/...) працюють лише для користувача з is_admin = 1
і лише не через Cloudflare, тобто з цього комп'ютера або через Tailscale:

    curl.exe -c admin.txt -X POST https://desktop-gtelcpk.taile8bb24.ts.net/login -H "Content-Type: application/json" --data-binary "@login.json"
    curl.exe -b admin.txt https://desktop-gtelcpk.taile8bb24.ts.net/admin/log
    curl.exe -b admin.txt https://api.andrienkova.pp.ua/admin/log      (через тунель: 404)

Адміністратором користувач стає лише так: python make_admin.py ЛОГІН на самому сервері.
Маршруту «зробити мене адміном» немає.


## Резервні копії

python backup.py копіює базу в теку backups/ з датою в назві. Щодня о 20:00 запускається планувальником Windows.

## Безпека

| Адмінка з інтернету | закрито | правило тунелю (404), перевірка CF-Connecting-IP, вхід під адміністратором (is_admin) |
| Паролі в базі | закрито | зберігаються лише хеші (werkzeug scrypt), відкритих паролів немає |
| Чужі дані | закрито | кожен запит має WHERE user_id = ?, чужий запис дає 404 |
| Підроблений cookie входу | закрито | cookie підписаний SECRET_KEY з .env, Secure + HttpOnly + SameSite=Lax |
| Підбір паролів, відкрита реєстрація | частково | однакова відповідь на неправильний логін і пароль, пароль від 8 символів; ліміт запитів Cloudflare діє на /items, а /login і /register можна додати до правила |

| Загроза | Статус | Чим закрита і як перевірено |
|---|---|---|
| SQL-ін'єкція | закрито | усі запити до бази з параметрами `?`. Перевірено: у категорію введено `'; DROP TABLE items; --`, запис додався як звичайний текст, таблиця ціла |
| XSS у фронтенді | закрито | дані виводяться через textContent. Перевірено: у коментар введено `<img src=x onerror=alert(1)>`, вікно alert не з'явилось, текст показано як є |
| Сервер розробки в інтернеті | закрито | тунель дивиться на waitress, а не на Flask з debug=True |
| Доступ в обхід Cloudflare | закрито | waitress слухає лише 127.0.0.1, публічної адреси немає |
| Флуд запитами | закрито | rate limiting у Cloudflare (20 запитів за 10 секунд на /items). Перевірено: серія запитів дала код 429 |
| Адмінка з інтернету | закрито | правило в тунелі (404), перевірка заголовка CF-Connecting-IP, токен. Перевірено: з телефона /admin/export дає 404 |
| Доступ до адмінки з Tailscale | закрито | без токена 403, з токеном відповідь 200. Без Tailscale адреса не відкривається |
| Небажаний трафік | закрито | Bot Fight Mode увімкнено, блокування за IP перевірено і правило видалено |
| Секрети в git | закрито | .env і backups/ у .gitignore, на GitHub файлу .env немає |
| Втрата даних | закрито | backup.py щодня о 20:00 (планувальник Windows), копію відкрито й перевірено кількість записів |
| Вразливі бібліотеки | перевірено | pip-audit -r requirements.txt: «No known vulnerabilities found» |

## Структура проєкту

- `models.py` — клас `Item` (запис про екскурсію). Сам перевіряє поля: число замість тексту, не від'ємне, дата у форматі РРРР-ММ-ДД.
- `logic.py` — підрахунки (суми за категоріями і місяцями, пошук, найбільша витрата), працюють зі списком `Item`.
- `storage.py` — робота з базою SQLite.
- `app.py` — маршрути Flask.
- `cli.py` — консольна версія (add, list, find, report).
- `migrate.py` — одноразове перенесення старої бази в новий формат.
- `backup.py` — резервна копія бази.
- `tests/` — тести pytest.

## База даних

SQLite, файл data.db. Три таблиці:

- `categories`: id, name (унікальна), monthly_limit (місячний ліміт витрат, може бути порожнім).
- `items`: id, date, title, category_id (посилання на categories), amount, duration, note.
- `audit_log`: id, ts (час), action (add, delete, set_limit, migrate), item_id, details.

Зв'язок: кожен запис у `items` належить рівно одній категорії. У кожному підключенні
увімкнено `PRAGMA foreign_keys = ON`, тож база не дозволить посилання на неіснуючу категорію.
Назви "Музей" і "музей" вважаються однією категорією.
### Користувачі

Таблиця users: id, login (унікальний, без різниці великі/малі літери), password_hash,
is_admin, created. Пароль у базі ніколи не зберігається, лише хеш (werkzeug, scrypt).
У items є user_id: кожен запис належить користувачу. У audit_log є user_id:
журнал показує, хто саме додав або видалив запис.

### Вхід і cookie

Після входу сервер ставить підписаний cookie з номером користувача:
Secure (лише HTTPS), HttpOnly (JavaScript його не бачить), SameSite=Lax, живе 7 днів.
Сайт і API на піддоменах одного домену, тому cookie ходить між ними.
Для цього в CORS увімкнено supports_credentials, а у фронтенді кожен fetch йде з credentials: "include".
На неправильний логін і неправильний пароль сервер відповідає однаково,
щоб не підказувати, які логіни існують.

### Міграція на користувачів (лабораторна 12)

Одноразово, при зупиненому сервері:

    python backup.py
    python migrate_users.py ВАШ_ЛОГІН
    python make_admin.py ВАШ_ЛОГІН

Скрипт сам робить копію бази, створює користувача і приписує йому всі наявні записи
в одній транзакції (перевіряє, що кількість і сума записів не змінились).

## Звіт через JOIN

GET /report/categories?month=2026-11 повертає суму витрат за категоріями за вказаний місяць
разом із місячним лімітом і ознакою `over_limit` (чи перевищено ліміт). Без `month` рахуються всі записи.
Запит об'єднує таблиці items і categories:

    SELECT c.name, SUM(i.amount) AS total, c.monthly_limit
    FROM items i JOIN categories c ON c.id = i.category_id
    WHERE i.date LIKE '2026-11-%'
    GROUP BY c.id ORDER BY total DESC;

## Журнал дій

Кожне додавання і видалення запису, а також зміна ліміту категорії записується в `audit_log`
в одній транзакції з основною дією. Переглянути останні записи (лише з цього комп'ютера або через Tailscale):

    curl -H "X-Admin-Token: ТОКЕН" "http://127.0.0.1:8000/admin/log?limit=50"

Задати місячний ліміт категорії:

    curl -X PUT -H "X-Admin-Token: ТОКЕН" -H "Content-Type: application/json" -d "{\"monthly_limit\": 500}" "http://127.0.0.1:8000/admin/categories/музей"

## Міграція старої бази

Якщо база ще у старому форматі (категорія текстом у таблиці items), сервер не запуститься
і підкаже запустити міграцію. Один раз:

    python migrate.py

Скрипт сам робить копію бази в теку backups, переносить усі записи в одній транзакції,
перевіряє, що кількість записів і загальна сума збіглися, і лише тоді підтверджує зміни.
Стара таблиця лишається під назвою items_old. Повторний запуск нічого не змінює.

## Тести

Тести написані на pytest і не торкаються справжньої бази: кожен тест працює з тимчасовою.

    pip install -r requirements.txt
    pytest -v

Що перевіряється:

- `tests/test_logic.py`: підрахунки, пошук, клас Item (текст замість числа, від'ємні значення, неправильна дата);
- `tests/test_app.py`: маршрути Flask, помилкові запити (код 400), захист адмінки (403 без токена, 404 через Cloudflare),
  звіт через JOIN, журнал дій;
- `tests/test_migrate.py`: перенесення старої бази без втрат і безпечний повторний запуск.
